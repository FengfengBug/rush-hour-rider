## 1. 项目一句话定义

一款基于纯 Three.js 程序化 Low-Poly 3D 城市场景的第三人称电动车外卖配送模拟器：玩家在 3.5 分钟高密度午高峰街区中骑车穿梭、边操作拟真骑手手机 App 抢单导航、边应对现实配送突发事件，并在收工后通过《算法时间账本》看见每一分钟的现实损耗，以及“若平台多给 5 分钟缓冲”的量化改变。

## 2. 技术选型与“防烂尾”硬红线

### 2.1 技术栈（轻量、零外链、秒开）
- **前端与构建**：Vite + React 19 + TypeScript + 原生 CSS
- **3D 引擎**：原生 **Three.js**（**不引入 `@react-three/fiber`**，保证渲染循环与 React HUD 完全解耦、60fps 稳定且避免版本兼容坑）
- **图标与音频**：`lucide-react` + 浏览器原生 **Web Audio API** 程序化合成音效
- **数据存储**：`localStorage` 仅存最高分/历史战绩与静音偏好，**无后端、无账号、免登录开箱即玩**

### 2.2 必须死守的 5 条红线
1. **零外部重型资产**：严禁下载外部 GLB/FBX 模型、高清贴图包或 MP3 音频；所有 3D 建筑、骑手、电动车、车辆均用 Three.js 基础几何体程序化拼装，店铺招牌用 Canvas 2D 动态绘制纹理，最终生产包严格控制在 **< 2–3 MB**，保证 Qoder Sites 公网秒开。
2. **假物理、强手感**：严禁接入 Rapier/Ammo/Cannon 等重型 3D 刚体物理引擎；电动车使用平面街机驾驶模型（速度/加速度/转弯半径 + 车身压弯纯视觉倾斜）+ **2D AABB 建筑碰撞滑墙回推**，绝不翻车、绝不穿模卡死。
3. **高密度微缩街区，不做空旷大世界**：固定为 **4×4 街区（约 360m×360m）** 的中国风微缩城市（美食街、老旧小区、CBD 写字楼、社区医院、换电柜），建筑与路灯/树木尽量使用 `InstancedMesh` 合批，保证普通核显笔记本 60fps。
4. **摒弃工程完美主义，坚持“可玩优先”**：
   - 不做“先画静态视觉稿等确认再接数据”的双倍返工流程；每个子任务直接交付**真实可运行、浏览器肉眼可见**的功能。
   - 不为 UI 布局或 3D 渲染写繁琐单测，只要求每个子任务 `npm run build` 零报错 + 浏览器实机可操作验证；仅对核心纯逻辑（如反事实重算、碰撞边界）按需补轻量校验。
   - 不做过度防御（如 localStorage 损坏恢复弹窗、复杂多级配置项），把 100% 精力集中在核心体验、视觉冲击与赛事亮点上。
5. **绝不做“精致的半成品”**：Day 3 结束前必须打通“接单 → 骑行 → 取餐 → 送达 → 结算”垂直切片；后续所有功能均在已可玩的主干上叠加。

## 3. 全局协作与截图留痕守则（给 AI 的执行协议）

1. **单任务推进，禁止贪大求全**：每次严格只执行 **1 个子任务（Task X.Y）**，绝不擅自跨步把一整天多个任务混在一起写，防止粗制滥造。
2. **动手前先对齐**：每次启动新任务前，先读取本文件，用 **3–5 行**简短汇报：当前任务 ID、计划改动的文件清单、预期可见效果，随后直接动手实现（除非存在阻塞冲突，否则不要反复请示拖慢节奏）。
3. **完成即验证**：每个子任务结束必须执行 `npm run build`（含 `tsc --noEmit`）通过，并确保浏览器运行控制台无阻塞报错。
4. **结束汇报与截图打卡协议（对应大赛“原创开发证明”要求）**：
   - 每个子任务实现完成后，在回复末尾必须固定输出两行：
     - `本次任务简要说明：<1–2 句概括完成内容与验证结果>`
     - `建议截图内容：<明确告诉用户截哪两张图：1) Qoder 开发过程/改动图；2) 浏览器实机运行画面>`
   - **当用户发送截图并回复“记录这条”**（或类似确认指令）时，AI 执行以下归档动作：
     1. 将用户提供的截图存入 `docs/screenshots/`，按 `YYYY-MM-DD-task-XX-01.png`（及 `-02.png`）命名；
     2. 在 `docs/DEVLOG.md` 追加一条记录（日期、任务编号与名称、简要说明、Markdown 相对路径图片引用）；
     3. 在本文件 `docs/ROADMAP.md` 中把该任务标记为 `已完成` 并补充一行完成说明；
     4. 执行 `git add`、`git commit`（规范中文 commit 信息）并 `git push` 到 GitHub（若 push 失败直接报告原因并停止，不盲目重试）。
   - 未经用户说“记录这条”前，不擅自修改 `DEVLOG.md` 或自动 push。
5. **模块边界清晰**：3D 引擎与游戏状态放 `src/game/`（不引入 React），UI 界面放 `src/components/`，两者通过受控的 Engine 实例方法和节流快照（10–15Hz）通信，避免 React 重渲染拖垮 3D 帧率。
